# UML 类图规范速查（建模时必读）

依据：OMG UML 2.5.1、Agile Modeling 类图风格指南（Scott Ambler）。本文件是 Step 2 建模的判定依据。

## 1. 类框（Class）

三栏矩形，**永远不画只有两栏的类**（要么三栏，要么空栏省略）：

```
┌──────────────────────────┐
│  <<Service>>             │ ← 构造型栏（可选，叠加在类名上方）
│  OrderService            │ ← 类名（abstract 斜体）
├──────────────────────────┤
|  - orderRepository       │ ← 属性栏
├──────────────────────────┤
|  + placeOrder(cmd): Order│ ← 操作栏
└──────────────────────────┘
```

成员标准语法：

```
可见性 名字: 类型 多重性 = 默认值 {性质}     ← 属性
可见性 名字(参数: 类型): 返回类型 {性质}    ← 操作
```

命名：类名 = 完整单数名词；属性名 = 领域名词；操作名 = 强动词。

## 2. 可见性（L3 必标；L2 可省；L1 不出现成员）

| 符号 | 含义 |
|---|---|
| `+` | public |
| `-` | private |
| `#` | protected |
| `~` | package / internal |

## 3. 修饰符

| 修饰符 | UML 记法 | PlantUML | Mermaid |
|---|---|---|---|
| static 成员 | 下划线 | `{static}` 前缀 | `$` 后缀 |
| abstract 成员 | 斜体 | `{abstract}` 前缀 | `*` 后缀 |
| abstract 类 | 类名斜体 | `abstract class Foo` | `<<Abstract>>` 注解 |

排序纪律：static 在实例成员前；成员按可见性降序（`+` → `#` → `~` → `-`）。

## 4. 构造型分组（决定颜色）

| 构造型 | 判定（代码特征） | 主题色 |
|---|---|---|
| `<<interface>>` | interface / protocol / trait / 纯虚基类 | 青系 |
| `<<abstract>>` | abstract class / 含未实现成员的基类 | 紫系 |
| `<<enumeration>>` | enum / 常量集 | 灰蓝系 |
| `<<Service>>` | 业务编排、用例层 | 黄系 |
| `<<Controller>>` | 入口、路由、触发器 | 橙系 |
| `<<Repository>>` | DAO / Gateway / 数据访问 | 棕系 |
| `<<Entity>>` | 实体、值对象、领域模型、DTO（领域类） | 绿系 |
| `<<external>>` | 第三方库、SDK、外部系统适配 | 灰系虚线边框 |

一个类只能进一个分组；拿不准时选它在**本图中扮演的角色**而不是它的语法类别（例如分析 Service 层时，一个被 service 持有的外部 SDK 类标 `<<external>>`）。

## 5. 关系判定表（核心）

记号方向规则：**三角/菱形/箭头指向谁是有语义的，画反即错。**

| 关系 | 语义 | 线 | 记号位置 | PlantUML | Mermaid |
|---|---|---|---|---|---|
| 泛化 | is-a | 实线 | 空心三角在**父类**端 | `Parent <|-- Child` | `Parent <\| Child` |
| 实现 | implements | **虚线** | 空心三角在**接口**端 | `IFoo <|.. Foo` | `IFoo \|.. Foo` |
| 组合 | 强拥有、生命周期绑定 | 实线 | **实心菱形在整体端** | `Whole *-- Part` | `Whole *-- Part` |
| 聚合 | 弱拥有、部分可独立 | 实线 | **空心菱形在整体端** | `Whole o-- Part` | `Whole o-- Part` |
| 关联 | 长期结构引用 | 实线 | 导航端普通开箭头 | `A --> B` | `A --> B` |
| 依赖 | 临时使用 | **虚线** | 开箭头指向被依赖方 | `A ..> B` | `A ..> B` |

### 代码证据 → 关系（跨语言）

| 代码证据 | 判定 |
|---|---|
| `class A extends B`（类→类）/ `class A(B)` Python 继承 / `A : B` C# | 泛化 |
| `implements IFoo` / `A(IFoo)` 协议继承 / implements 协议 / duck-typed 契约 | 实现 |
| 字段持有 + 构造中创建 + 级联销毁/持久化（`Order` 1 *-- 1..* `OrderItem`） | 组合 |
| 字段持有但对方独立创建/注入、可脱离存在（`Department` o-- `Employee`） | 聚合 |
| 字段/属性长期持有对方引用（含 DI 注入的字段） | 关联 |
| 仅出现在方法签名（参数/返回值）或方法体内局部变量 | 依赖 |
| 事件回调 / 观察者注册（`addListener(this)`） | 依赖（可加注说明） |
| 静态调用 / 工具类使用（`Utils.foo()`） | 依赖（通常**省略**，除非架构关键） |

### 关系使用纪律

- 不画传递可达的隐含关系；不画每个工具性依赖；
- 属性类型已表达的关系（`address: Address`）不再画线，除非多重性/语义重要；
- 聚合 vs 组合拿不准 → 画关联 + 注释，**不瞎放菱形**；
- 两个类之间有多条关联或自关联 → 每端加**角色名**；
- 多个类继承同一父类 → 用树状合并（PlantUML `skinparam groupInheritance 2`）。

## 6. 多重性（关联/聚合/组合必标）

| 写法 | 含义 |
|---|---|
| `1` | 恰好一个 |
| `0..1` | 零或一个 |
| `1..*` | 一或多 |
| `0..*` | 零或多（**写全，不用裸 `*`**） |
| `n` / `0..n` | 具体上限时使用 |

写法（PlantUML）：`Customer "1" *-- "1..*" Order : places >`——两端多重性 + 主动语态动词条目 + `>` 指示阅读方向。关联名从左到右可读，居中。

## 7. 布局纪律

- 父类在上、子类在下（LR 方向时：父在左）；
- 整体在左、部分在右；
- **接口与其实现类放同一个包**（适配器所在的层），跨包的实现线必然横穿包框、且拖长交叉（实测教训）；DDD 端口模式如需强调"接口属于应用层"，宁可加注说明也不跨包拉线；
- 关系尽量水平/垂直；用 `together {}` 聚拢内聚类，`-[hidden]->` 固定层次锚点；
- 信息量低的边（如"谁创建了这个类"的临时依赖）在 L2 密度下直接省略，减少交叉源；
- 包（package）表达命名空间/模块边界，颜色取自主题对应分组色系。

多重性豁免：Repository / Gateway 等基础设施访问类的关联**可不标多重性**——它们是访问语义而非拥有语义，强行标注反而误导。

## 8. 常见错误对照（发布前自查）

| 错误 | 正确 |
|---|---|
| 三角指向子类 | 三角指向父类/接口 |
| 继承画成 `-->` 实线箭头 | `<\|--` 空心三角实线 |
| 实现画成实线 | `<\|..` 虚线 |
| 菱形放在"部分"端 | 菱形在"整体"端 |
| 关联无多重性 / 裸 `*` | 两端标 `1` `0..1` `1..*` 等 |
| 所有类同色、无图例 | 构造型分色 + 图例必带 |
| 类只有两栏 / 罗列 getter | 三栏或省略空栏；L2 只留关键成员 |
| 成员无序 | static 前、可见性降序 |
| 30 个类挤一张图 | ≤10/图，拆总览+详图 |
| 接口画成普通类 | `<<interface>>` + 青色 + 三角虚线 |
